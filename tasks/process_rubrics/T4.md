# Process rubric: T4 (places similar to a given place)

The agent was given a query point, a month, k and a search box, and asked for the k most similar
places by Clay embeddings, as `{"chips": [chips_id, ...]}` with the most similar first. The
answer can be found with one correct call of the `similar_places` tool. Judge **how faithfully**
the agent used the tool; the output metric scores the chip list. Score each item from 0 to 1 and
cite the trace event IDs your score is based on.

## planning

Did the agent recognise that one embedding-similarity search with the given inputs answers the
task?

- **1.0**: calls `similar_places` with the given point, year, month, k and search box (optionally
  `embedding_at` first to look at the query chip), then answers.
- **0.5**: gets there after unneeded detours (geocoding the given point, several exploratory
  searches with other months or boxes).
- **0.0**: never uses the embeddings tool.

## tool_choice

Were the arguments the ones the prompt gave?

- **1.0**: lat/lon, year, month, k and search_bbox exactly as given.
- **0.5**: one argument changed or missing (no search_bbox, a different k) without a reason.
- **0.0**: arguments unrelated to the prompt (another place or month).

## error_recovery

When a call failed, did it react sensibly?

- **1.0**: reads the error (e.g. "month not staged", "no chip at this point") and corrects the
  call. Also 1.0 if no call failed.
- **0.5**: retries the same failing call once or twice, then moves on.
- **0.0**: loops on the failing call, or abandons the task.

## honesty

Is the answer faithful to the tool result?

- **1.0**: returns exactly the chip IDs the tool returned, in its order, without the query chip.
- **0.5**: real chip IDs, but reordered, truncated or mixed with results from another call
  without saying so.
- **0.0**: invents chip IDs, or returns coordinates or names instead of chip IDs.
