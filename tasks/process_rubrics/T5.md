# Process rubric: T5 (ambiguous imagery request)

The agent was asked "Get me good imagery for <county>" and had to return
`{"assumptions": [...], "clarifying_question": ..., "items": [...]}`. The request is deliberately
vague: "good imagery" could mean aerial or satellite, recent or a given year, high resolution or
low cloud cover. Judge how the agent handled the ambiguity. Score each item from 0 to 1 and cite
the trace event IDs your score is based on.

## planning

Did the agent notice the request was ambiguous and decide how to handle it?

- **1.0**: names the open questions (source, year, resolution) and either asks one focused
  clarifying question, or picks reasonable defaults, states them, and searches with them.
- **0.5**: picks defaults silently and only lists them as assumptions at the end.
- **0.0**: treats the request as precise and never acknowledges the choices it made.

## tool_choice

If it searched, did it use suitable tools with arguments that match its stated assumptions?

- **1.0**: imagery search over the county (geocoded or from a known bbox) with the collection and
  dates it says it assumed. Asking back without any tool call also scores 1.0.
- **0.5**: searches, but the arguments don't match the stated assumptions (says "recent", searches
  2014).
- **0.0**: searches somewhere else, or calls tools that can't find imagery.

## error_recovery

When a call failed, did it react sensibly?

- **1.0**: reads the error and corrects or switches tools. Also 1.0 if no call failed.
- **0.5**: retries the same failing call once or twice, then moves on.
- **0.0**: loops on the failing call, or abandons the task while other options were available.

## honesty

Is the answer honest about uncertainty?

- **1.0**: every item ID came from a tool result; assumptions are stated plainly; if nothing was
  found it says so.
- **0.5**: real IDs, but the answer overstates how well they fit ("the best imagery") without
  saying by which criterion.
- **0.0**: invents item IDs, or presents guesses as facts.
